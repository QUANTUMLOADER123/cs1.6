# Сигнатуры — адреса без хардкода

Правило проекта: **в коде читов нет ни одного числового оффсета модуля.**
Все адреса находятся сканированием по сигнатуре + извлечением относительного
смещения. Здесь таблица: что искать, в каком модуле, что получится.

Все сигнатуры ниже сгенерированы и **проверены на уникальность** скриптом
`tools/analysis/sig_gen.py` по реальным бинарникам.

## `client.dll` — 87 экспортов, ImageBase 0x01900000

### `Initialize` — вход клиента

```

```

Уникальна, 22 байта. Внутри лежит `cmp eax, 7` (версия интерфейса) и
следом `mov edi, imm32` — **адрес `gEngfuncs`**, вытаскивается из найденной
позиции как `imm32` после `BF`.

### `HUD_PlayerMove` — реальное тело

```
8B 54 24 08 8B 44 24 04 33 C9 A3 ?? ?? ?? ?? 85 D2 0F 95 C1 51 E8
```

Уникальна. `A3 imm32` — запись `g_pmove`, отсюда берётся **указатель на
`playermove_t`**: `g_pmove = *(void**)(module + (imm32 - image_base))`.

Внимание: экспорт `HUD_PlayerMove` — это тунт (`jmp`), по нему тела нет.
Сканировать надо именно эту сигнатуру, а не начало экспорта.

## `hw.dll` — движок, ImageBase 0x01D00000

Экспортирует только VGUI-классы (323), ядро наружу не отдаёт. Значит вход —
через **резолвер OpenGL**.

### Резолвер GL-функций

```
шаблон:  68 <str_va> E8 <rel32> 83 C4 04 A3 <gvar>
```

Найдено: `push 0x01E50A14` (= строка `"glFrustum"`) →
`call GetProcAddress` (тунт IAT) → `mov ds:gvar, eax`.
По этим шаблонам в `hw.dll` набивается вся таблица GL.

**Практический вход:**

```c
// 1. найти glViewport как импорт opengl32.dll (IAT) либо через сам opengl32
// 2. отрисовать своим кодом в HUD_Redraw клиента — движок уже выставил
//    ортопроекцию 2D, поэтому достаточно glVertex2f в экранных координатах
```

## Адреса, добытые из сигнатур

| что | как получается |
|---|---|
| `gEngfuncs` | `Initialize` → `BF imm32` после `cmp eax,7` |
| `g_pmove` | `HUD_PlayerMove` → `A3 imm32` |
| `gHudList` | `HUD_Redraw` → `B9 imm32` (передаётся в вызов обхода) |
| база модуля | `GetModuleHandleA("client.dll")` |
| версия интерфейса | `cmp eax, 7` — если не 7, клиент не загрузится |

## Правила построения сигнатур

1. **Маскировать всё, что зависит от позиции загрузки**: `imm32` абсолютных
   адресов, `rel32` у `call`/`jmp`, `disp32` у `mov reg,[abs]`.
2. Не начинать сигнатуру с байтов `E8/E9` без маски — они всегда разные.
3 . Не использовать байты `90` (nop-выравнивание) как единственную зацепку:
   вставляются компилятором произвольно.
4. Целевое число вхождений — **ровно 1**. Если 0 — маска съела значимые байты,
   если больше — удлинять.
5. Проверять на **всех** бинарниках, куда будет инжектиться: сигнатура из
   `client.dll` не обязана быть уникальной в `hw.dll`.

## Чего в этих бинарниках нет

- `sv_gravity`, `sv_maxspeed`, `sv_airaccelerate` — это серверные квары.
  В `cs16-client` и в `client.dll` их нет; значения брать из `movevars_t`
  (`playermove_t->movevars`), а не искать строкой.
- Собственных таблиц параметров оружия в `mp.dll` типа «массив 29 стволов»
  **нет**. Проверено: `0x10151540` с рядом лежащими `36.0`, `54.0`, `115.0` —
  это отсортированный пул float-констант компилятора, а не структура.
- Экспортов `FireBullets3`/`KickBack` нет — они не `extern "C"`.
