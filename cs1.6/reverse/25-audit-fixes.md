# 25. Аудит: что было сломано и как исправлено

Этот документ — журнал дефектов, найденных сплошной проверкой кода
против исходников FWGS/cs16-client. Каждый дефект был молчаливым:
фича «включалась» в меню, ничего не роняло, но не работала.

## 1. Биты кнопок: приседание вместо удара

В `sh_knife.cpp` удар ножом ставился битом `4`. По `common/in_buttons.h:25`:

```
IN_ATTACK = 1<<0 = 0x001
IN_JUMP   = 1<<1 = 0x002
IN_DUCK   = 1<<2 = 0x004
```

`0x004` — это приседание. Нож-бот в упор заставлял игрока присесть.
Удар (`1`) стоял только в ветке «цель дальше дистанции удара», где он
бесполезен.

Исправлено: `sh_in_attack` всегда при наличии цели. Введены
именованные константы для всех кнопок.

## 2. Glow: renderfx 20 вместо 19

`ent->curstate.renderfx = 20`. Пересчёт `kRenderFx` (`common/const.h:714`)
с нуля: `19 = GlowShell`, `20 = ClampMinScale` (защита спрайта от
уменьшения). Модель игрока со `renderfx = 20` не светится вообще.

Исправлено: `sh_renderfx_glowshell = 19`.

## 3. `HUD_TxferLocalOverrides`: сломанные присед и стрельба

Хук обнулял `iuser3` (при `fake_duck`) и `iuser4` (при `hideshot`).
Но `entity.cpp:85` прямо подписывает:

```c
state->iuser3 = client->iuser3;   // Duck prevention
state->iuser4 = client->iuser4;   // Fire prevention
```

Это **разрешение**, а не запрет: сервер пишет `1`, когда действие
разрешено. Обнуление отнимало разрешение — игрок не мог присесть и
не мог выстрелить ни на одном сервере.

Исправлено: хук прозрачный. `fake_duck` реализован через `IN_DUCK` в
`CreateMove` (движок сам опускает камеру). `hideshot` — через
`EF_MUZZLEFLASH` в `HUD_AddEntity`.

## 4. Индексация игроков: пустой ESP

`g_players[]` заполнялся плотно (`0, 1, 2, …`), а `sh_player_get(i)`
вызывался с номером игрока (`1..32`) в девяти местах. При игроках с
номерами 5 и 17 функции `get(5)` и `get(17)` возвращали `0`.

Исправлено: массив индексируется напрямую номером игрока, `collect()`
пишет в `g_players[i]`, `get()` проверяет `g_players[index].ent`,
все циклы — `1..32`.

## 5. `sh_player_local()` возвращала `0`

Заглушка. Её используют радар, нож-бот, grenade predict, ESP —
все молча не работали. Реализовано через `g_pmove->player_index`.

## 6. `g_trace_fn` никогда не устанавливался

`sh_engine_trace_setup()` была пустой, `sh_set_trace_fn()` не вызывался.
Следствие: `sh_player_visible()` всегда отдавала «видно», автован и
нож-бот били сквозь стены.

Реализовано: обёртка над `g_pmove->pm_player_trace` (смещение
`0x4F680`, зафиксировано `typedef`-assert'ом).

Дополнительно инвертировалась логика: возвращалось `hit != 0`
(попал = видно) вместо `hit == 0`.

## 7. `FL_`-флаги: перепутаны значения

```
было: FL_DUCKING 0x4,   FL_FROZEN 0x4000
надо: FL_DUCKING 0x4000, FL_FROZEN 0x1000
```

`0x4` — это не `FL_`, а `IN_DUCK`. Плюс оба места читали
`curstate.eflags`, а `eflags` — **байт** (`entity_state.h:55`) для
`EF_*`-эффектов; `FL_*`-флаги лежат в `pmove->flags`, а в
`entity_state_t` поля `flags` нет вовсе.

Исправлено: высота приседа определяется по `curstate.usehull == 1`.

## 8. `weapon_id` = индекс модели, а не оружие

`p->weapon_id = ent->curstate.weaponmodel` — это индекс в кэше моделей.
Для игрока с AK-47 он мог быть `87`, поэтому все проверки
`weapon_id == 28` не срабатывали никогда: иконки, нож-бот, отдача,
super toss.

Исправлено: `sh_weapon_from_model` берёт `model->name` через
`GetModelByIndex`, отрезает `models/` и `w_`/`v_`, сравнивает с
таблицей.

## 9. `double_tap` блокировал стрельбу

```c
if (!double_tap || sh_rage_double_tap(...)) cmd->buttons |= IN_ATTACK;
```

Внутри `sh_rage_double_tap` требовалось `next_attack_time` в узком
окне **и** уже нажатая кнопка атаки. С включённым double tap выстрел
почти не ставился.

Исправлено: проверяется только «оружие готово».

## 10. `quick_stop`: инвертированное условие + `else if`

- `if (speed < maxspeed * 0.9f) return;` — отсекало низкие скорости,
  хотя по `PM_Friction` (`pm_shared.cpp:1140`) торможение тем сильнее,
  чем выше скорость, и нужно оно на разгоне.
- Требовалось `IN_ATTACK` — торможение к атаке не относится.
- Вызов стоял в `else if` от автострейфера, то есть с включённым
  автострейфером `quick_stop` не вызывался никогда.

## 11. `no_spread` компенсировал `punchangle.z`

`punchangle.z` в GoldSrc — это roll от жёсткого приземления
(`pm_shared.cpp:2615`: `punchangle[2] = flFallVelocity * 0.013`), а не
разброс. Реализовано заново: воспроизведение `SharedRandom` по seed'у
и вычитание смещения из `viewangles`.

## 12. `super_toss` двигал `forwardmove`

На силу броска движение не влияет. По `dlls/wpn_shared/wpn_hegrenade.cpp:195`:

```c
angThrow.x = -10 + angThrow.x * (80/90)   // при x < 0
flVel = (90 - angThrow.x) * 6             // кап 750
```

Сила зависит только от питча. Реализована обратная задача: по
желаемой скорости находится питч.

## 13. `no_smoke`: неверный `renderfx` и потерянный параметр

Проверка `renderfx == 20` не имеет смысла (см. п.2). Хук
`HUD_AddEntity` терял **третий параметр** — имя модели:

```c
int HUD_AddEntity(int type, cl_entity_s *ent, const char *modelname)
```

Теперь имя модели доступно, и `no_smoke` фильтрует по нему.

## 14. Дубликаты в конфиге

`bhop`, `thirdperson`, `thirdperson_dist`, `spectator_list` были
объявлены дважды — в `visuals` и в `misc`. Меню крутило одну копию,
код читал другую. Удалены дубли из `misc`.

## 15. `nightmode` сводил цвет к среднему

Три ползунка R/G/B давали одно число `(r+g+b)/3`. Заменено на
`lum = 0.299r + 0.587g + 0.114b`, `mono = 1 - lum`.

Попутно: cvar `gl_monolights_color` **не существует** (в `hw.dll`
0 совпадений) — попытка его выставить убрана до коммита.

## 16. `pmtrace_t` и `playermove_t`: неверные размеры

`pmtrace_t` = **68** (`0x44`), а не 64: пропущено `vec3_t deltavelocity`
между `ent` и `hitgroup`, а `plane` — это `{vec3_t normal; float dist;}`.

`playermove_t` = **325308** (`0x4F6BC`), а не 1508. Четыре ловушки:

1. `pmtrace_t` 68, не 64 (`deltavelocity`).
2. `physinfo` — 512 байт (в `entity_state_t` — 256).
3. `qboolean` = `int` (4 байта), не `bool`.
4. Указателей-членов 26 (внутри есть параметры `pfnIgnore` — не поля).

## Методика

Все дефекты найдены одним способом: **брать число или флаг из
исходника, а не из памяти**. Каждый раз, когда в коде стояла
литеральная константа (`4`, `20`, `1508`, `0x4`), она оказывалась
неверной или означала не то.

Правило на будущее: любая константа должна иметь имя, а имя — ссылку
на строку в `cs1.6-ref`.

## Продолжение: баллистика, события, движение

### 17. `weapon_id` из индекса модели (см. п.8) — и порождённая им цепочка

Когда оружие стало определяться верно, вскрылось, что от него зависело
ещё три модуля, каждый со своей ошибкой:

- `sh_spread_compute` вызывался с `up_base * 10` — величиной **отдачи**.
  Разброс и отдача — разные вещи: у AK стоя разброс 0.0096 рад
  (≈0.55°), а компенсировалось 15°.
- `sh_autowall` считал урон константой 30 и пробитие 2 для любого
  оружия. С AWP это 30 вместо 115, с ножом — тоже 30 (нож «пробивал»
  стены).
- `sh_recoil_for` отдавал по умолчанию запись «AK в бегу» (1.5/0.45),
  то есть стоя компенсировалось завышенное.

Все три переписаны по исходникам: таблица разброса с учётом состояния
(`wpn_ak47.cpp:82-93`), таблица урона и пробития по 31 стволу
(`FireBullets3`, 29 файлов), таблица `KickBack` по 13 стволам ×
4 состояния.

### 18. Разброс — угловой, а не мировые координаты

```
было:  to.x += sp.x; to.y += sp.y;
надо:  vecDir[i] = vecDirShooting[i] + x * flSpread * right[i]
                  + y * flSpread * up[i]        (ev_hldm.cpp:376)
```

Смещение по осям мира даёт разный результат в зависимости от того,
куда смотришь. Реализовано `sh_spread_trace_dir`.

### 19. `random_seed` был недоступен — и стал доступен

`FireBullets3` получает `m_pPlayer->random_seed` (`wpn_ak47.cpp:141`),
но в клиенте этот seed приходит только в `HUD_PostRunCmd`, который
**экспортируется** `client.dll` (проверено `objdump -p`) и раньше не
хукался. Теперь сохраняется и используется.

Честная граница: `HUD_PostRunCmd` вызывается **после** просчёта
команд, поэтому предсказать свой выстрел нельзя — можно лишь
проверить, куда он ушёл.

### 20. `HUD_StudioEvent` не хукался — выстрелы других игроков были невидимы

`cl_dll/entity.cpp:340-362`: события 5001/5011/5021/5031 — это
`R_MuzzleFlash` по attachment 0..3 (у двустволки два ствола). Все они
проходили мимо. Теперь через них рисуются трассеры стреляющих и
считается индикатор вражеского огня.

Попутно: старый индикатор срабатывал по `curstate.weaponanim` ∈ {1,2,3}.
Но `weaponanim` — номер **анимации**, своя нумерация у каждого оружия,
и она меняется при доставании и перезарядке. Заменено на событие.

### 21. `char_texture` всегда 0 — таблица материалов не работала

`sh_rage_trace` писал `out->char_texture = 0`. Реализовано через
`playermove->pm_trace_texture` (`pm_defs.h:194`): движок отдаёт имя
текстуры, тип — по префиксу имени, как в `PM_TextureType`
(`pm_shared.cpp:170-206`).

Сама таблица была на числах: `84` считалось «металлом», а это `'T'`
(плитка); металла `'M'` (77) не было вовсе. Переписана на 13 символов
из `pm_materials.h:38-50`.

### 22. `KickBack`: перепутаны состояния

В исходнике четыре вызова подряд: бег, воздух, присед, стоит
(`wpn_ak47.cpp:164-179`). В таблице первая запись была «бег», и она же
использовалась по умолчанию. У пистолетов и AWP `KickBack` в клиенте
**не вызывается вовсе** — отдача у них внутри `mp.dll`.

### 23. Автострейфер разгонял выше лимита движка

`pm_shared.cpp:2336`:

```c
maxscaledspeed = BUNNYJUMP_MAX_SPEED_FACTOR * pmove->maxspeed;  // 1.2x
if (spd > maxscaledspeed) {
    fraction = (maxscaledspeed / spd) * 0.8;
    VectorScale(pmove->velocity, fraction, pmove->velocity);
}
```

С `forwardmove = 450` игрок разгонялся выше `1.2 * 320 = 384`,
и движок на следующем прыжке резал скорость до 307. Bhop становился
медленнее ходьбы. Добавлена проверка скорости.

### 24. Bhop не отпускал кнопку прыжка

`pm_shared.cpp:2432`: `if (pmove->oldbuttons & IN_JUMP) return;`
и в конце `pmove->oldbuttons |= IN_JUMP` («не прыгать, пока не
отпустят»). Код ставил кнопку каждый кадр — прыжок не проходил.
Добавлены кадры отпускания.

### 25. `nightmode` управлял не теми cvar'ами

Полный список `gl_*` из `hw.dll` — 24 имени. `gl_overbright` — это
булево «пересвет», `gl_flashblend` — «рисовать блики спрайтом».
Ни то, ни другое не яркость. Заменено на `gamma`, `brightness`,
`lightgamma`, `texgamma`, `gl_monolights`.

Произвольный цвет мира в GoldSrc задать **нельзя** — свет запечён
в карту.

### 26. `chams` гасил glow

```c
if (chams || glow) { if (glow) {...} else { renderfx = 0; } }
```

При включённом `chams` и выключенном `glow` ставился `renderfx = 0` —
обычная раскраска, никакого чеймса. Разведено на две ветки;
чеймс через `kRenderTransAlpha` (4), а не `kRenderTransTexture` (2):
последний в `hw.dll` идёт без записи в Z-буфер.

### 27. Десинк флипался каждый кадр

`g_desync_flip = !g_desync_flip` на каждом вызове `CreateMove` —
при 100 fps тело дёргается 100 раз в секунду, сервер усредняет это
в ноль. Заменено на номер тика: `(ticks / desync_ticks) & 1`.

Заодно `movement_fix` получал углы с ненулевым `z` (roll) и
испорченным питчем — теперь обнуляется по `x` и `z` до применения.

### 28. Fakelag: двойной счёт и дрейф интервала

- `sh_fakelag_should_choke` увеличивала счётчик, и её же вызывал
  `sh_fakelag_run` — за кадр проходило два шага, «тиков N» давало N/2.
- `next_send_time = now + interval` вместо `current + interval` —
  отправка отодвигалась каждый кадр, пакеты не уходили вовсе.
- Не было проверки на мусор: по указателю из паттерна писался сырой
  `float`. Если паттерн попал не туда, туда ушло бы `1e30` и игра
  перестала бы отправлять команды.

### 29. Парсер демок: `dirs_offset` не применялся

`sh_demo_header_t` — 544 байта (зафиксировано `typedef`-проверкой).
Поле `dirs_offset` читалось шестым, а разбор блоков начинался с
жёсткого смещения 540.

### 30. `flat_textures` не убирал «объём»

Добавлен `r_lightmap = 1` (полное освещение, без запечённых теней)
к `gl_picmip 2` и `r_detailtextures 0`.

## Итог аудита

| метрика | было | стало |
|---|---|---|
| хуков | 9 | 11 |
| полей конфига без эффекта | 16 | 0 |
| констант-литералов в логике | ~40 | 0 |
| таблиц по исходникам | 3 | 9 |
| размер DLL | 371 200 | 380 416 |

Каждый дефект найден одним способом: **число или флаг берётся из
исходника, а не из памяти**. Любая литеральная константа (`4`, `20`,
`84`, `1508`, `0x4`) оказывалась либо неверной, либо означающей не то.
