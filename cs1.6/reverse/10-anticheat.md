# Реверс CS 1.6 — античит: что он видит

Честный разбор. Не «как обойти», а «какие механизмы существуют и как они
работают» — чтобы понимать границы SDK.

---

## 1. Что реально есть в этих бинарниках

| механизм | найдено | где |
|---|---|---|
| VAC в `client.dll` | **нет** | строка `VAC` встречается 0 раз |
| VAC в `hw.dll` | **частично** | только режим соединения со Steam |
| Steam-аутентификация | да | `Unable to connect to Steam`, `getchallenge steam` |
| «secure mode» | да | `(secure mode enabled, connected to Steam3)` |
| проверка HWID/железа | нет | |
| сканирование памяти клиента | **нет в этих файлах** | |

Вывод: **проверка читов не живёт в `client.dll`/`hw.dll`**. Эти файлы —
игровой код, они не знают, что в их процессе есть лишняя DLL.

---

## 2. Где живёт VAC

VAC — отдельный модуль, который Steam инжектит в процесс **после**
подключения к защищённому серверу. В этих бинарниках его нет вообще.

Движок только сообщает статус:

```
hw.dll:  "(secure mode enabled, connected to Steam3)"
hw.dll:  "(secure mode enabled, disconnected from Steam3)"
```

Это значит: движок знает, защищён ли сервер, но **сам ничего не проверяет**.
Проверяющий модуль приходит снаружи.

---

## 3. Что VAC может видеть в клиенте GoldSrc

Исторически (и это важно понимать) VAC для GoldSrc умел:

| проверка | как |
|---|---|
| список загруженных модулей | `EnumProcessModules` / PEB walk |
| сигнатуры известных читов | сканирование памяти по байтам |
| целостность `client.dll`/`hw.dll` | хеш `.text` |
| подозрительные хуки | сравнение первых байт функций с оригиналом |
| отладочные флаги | `IsDebuggerPresent`, `PEB->BeingDebugged` |

**Три из пяти пунктов ловят наивный чит.** В частности:

- хук `CL_CreateMove` через MinHook **меняет первые байты функции**
  (`jmp`) — это прямое расхождение с оригиналом;
- свежеинжекченная DLL видна в списке модулей;
- неизвестный модуль в процессе — достаточный повод.

---

## 4. Что VAC видит в этом конкретном SDK

Проверяю по факту кода `skeethook_1_6`:

| признак | есть? | комментарий |
|---|---|---|
| инжект DLL | **да** | обязательное условие работы |
| хуки MinHook на `CL_CreateMove`, `HUD_Redraw`, `HUD_PlayerMove`, `HUD_AddEntity` | **да** | 4 `jmp` в `.text` `client.dll` |
| встроенный шрифт/строка `skeethook_1_6` | **да** | видна в памяти как строка |
| конфиг-файл `<exe>.cfg` | **да** | файл на диске |
| изменение `rendermode` сущностей | да | видно на сервере только косвенно |
| сетевое преимущество | **да** | aimbot/autowall дают статистику |

То есть SDK **не является «невидимым»**. Это осознанный инструмент для
своего сервера / офлайна, а не для игры на защищённых серверах.

---

## 5. Серверная сторона: что видит сервер, а не клиент

Даже без VAC сервер замечает часть чита:

| признак | как ловится |
|---|---|
| слишком точное наведение | статистика по углам между тиками |
| стрельба без видимости | `AddToFullPack` не отправлял цель |
| autowall сквозь стены | урон через геометрию, которую сервер считает непроходимой |
| bhop без потери скорости | распределение скоростей |
| antiaim | `usercmd_t.viewangles` вне физически достижимых |
| **скорость выше `1.2 * maxspeed`** | `PM_PreventMegaBunnyJumping` срезает — аномалия видна |

Последнее — прямое следствие реверса: сервер **сам** ограничивает bhop
фактором 1.2, значит «невозможной» скорости не будет, но частота прыжков
без потери скорости — аномалия.

---

## 6. Границы: что SDK делает и чего не делает

**Делает:**
- читает `playermove_t`, `cl_entity_t`, `g_globals` — это **своя** память
  клиента, не сервера;
- двигает `usercmd_t.viewangles` — это **то, что клиент и так шлёт**;
- рисует поверх — чисто локально;
- меняет `rendermode` — локально (если не считать, что это меняет
  отправляемое состояние — не меняет).

**Не делает:**
- не пишет в память сервера (его нет в процессе);
- не подделывает пакеты;
- не трогает хеши модулей;
- не обходит VAC.

---

## 7. Вывод

Этот реверс и SDK — **исследовательский инструмент**:

1. Все механики восстановлены из открытых исходников и подтверждены
   бинарно — это делает SDK *правильным*, а не «набором оффсетов».
2. Запускать его следует на **своём сервере** (`sv_lan 1`, listen server)
   или в офлайне с ботами.
3. На защищённых серверах Steam использование означает бан — VAC для
   GoldSrc ловит именно инжект + хуки, а не «умность» чита.

Если задача — **изучать игру**, SDK даёт полный доступ к её внутренностям
легально: структуры, физика, HUD, оружие, сеть. Если задача — играть с
преимуществом на чужих серверах, никакой реверс этого не меняет: детект
идёт по факту инжекта.

---

## 8. Что можно сделать честно

| идея | как |
|---|---|
| свой сервер с ботами | listen server, `mp_*` квары |
| тренировка движения | offline, `sv_airaccelerate` |
| изучение HUD | локальная отрисовка, не влияет на игру |
| разбор демок | `.dem` → парсинг через `demo_api` |
| **SDK как плагин для своего сервера** | ReGameDLL `IReGameApi` hooks — легальный путь |

Последнее — самое интересное: ReGameDLL (который и есть ваш `mp.dll`)
предоставляет **официальный API** для расширений (`IReGameApi`,
`CReGameHookchains`). Через него можно делать то же самое, но по правилам
сервера.
