# skeethook 1.6

**Новая база: gold-sdk.** См. `docs/BASE.md`.

## Файл

`skeethook_1_6.dll`

## Установка

1. Положить `skeethook_1_6.dll` рядом с `hl.exe`.
2. Убедиться, что рядом лежит `SDL2.dll` (нужна для курсора).
3. Инжектить в `hl.exe`.
4. **INSERT** — открыть/закрыть меню. **END** — выгрузить.

## Управление в меню

- Мышь — клики (SDL2 держит курсор отпущенным, пока меню открыто).
- Колесо — прокрутка списков.
- Меню таскается за шапку.

## Что включено по умолчанию

Только ESP: `box`, `name`, `enemies_only`.
Всё остальное выключено — включай сам.

## Откат к эталону (эта сборка)

Причина предыдущей поломки найдена и устранена. Меню не появлялось не
из-за CRT и не из-за платформы:

1. Я подменил `modules::engine` с `next_engine_mini.dll` на `hw.dll`.
   В кастомном клиенте движок — именно `next_engine_mini.dll`. Паттерны
   не находились, `engine::initialize()` возвращала `false`.
2. Я переписал цепочку инициализации и выбросил из неё
   `engine_cvars`, `engine_tracers`, `studio`, `weapons`.
3. Итог: `hooks::initialize()` не вызывалась → `SwapBuffers`
   не хукался → меню не рисовалось вообще.

Откачено: `main.cpp`, `hooks.cpp`, `render.cpp`, `cursor.*`,
`modules.hpp`, `imgui_impl_opengl.*` — теперь **байт в байт как в
gold-sdk**. Осталось ровно две правки, обе вынужденные:
- `event_manager.cpp` — `_ReturnAddress()` (MSVC) → `__builtin_return_address(0)`, иначе mingw не соберёт;
- `menu.cpp` — уникальные `##` у одинаковых подписей.

Дополнительно: в цикле инициализации теперь пишется в консоль **номер
шага**, который не прошёл. Поведение прежнее (retry 200 мс), но если
снова не запустится — в консоли будет видно, где именно.
